# LicenciaGov – guia para desenvolvedores e agentes

Especificação completa: `docs/SPEC.md` (fonte da verdade). Stack: Next.js 15 (App Router) + TypeScript + Tailwind v4 + Prisma 6 + PostgreSQL 16.

## Ambiente local
- Postgres: `service postgresql start` (DB `licenciagov`, user/senha `postgres`). `.env` na raiz (modelo em `.env.example`).
- `npx prisma migrate deploy && npm run seed:base` (ou `seed:demo` com dados completos) — senha de todos os usuários demo: `Demo@2026licencia`
  (admin@licenciagov.demo, tec.consorcio1@…, tecnico.lor@…, gestor.lor@…, fiscal.lor@…, tecnico.cse@…, tecnico.ssr@…, sema@…, laticinio@… (requerente) etc. – ver `prisma/seed/base.ts`).
- Dados demo são **fictícios**: organização "Consórcio Intermunicipal de Demonstração" (CID-DEMO) e municípios Lagoa do Orvalho (LOR, principal), Serra Serena (SSR), Campo das Seriemas (CSE), Pedra do Candeeiro (PCA), Alto do Umbuzeiro (AUM), Várzea do Mandacaru (VMA) – códigos IBGE fictícios `99…`. Nunca usar nomes de municípios/consórcios reais em seed, testes ou textos do app – **exceto clientes reais cadastrados por onboarding** (ex.: Prefeitura de Riachão das Neves, `prisma/seed/clientes/`), cujos dados de demonstração (empresas, pessoas, CPF/CNPJ, CAR) continuam fictícios. Exceção aprovada: o conjunto da **PoC da licitação do CDS Piemonte** (`prisma/seed/clientes/cds-piemonte.json` + `cds-poc-demo.ts`, `E2E_DATASET=poc-cds`, ver `docs/poc-cds.md`) usa o consórcio e os 8 municípios reais e só pode ser carregado no ambiente da PoC (nunca junto do demo público) – não "corrija" esses nomes. `DEMO_MODE=true` exibe a faixa "Ambiente de demonstração".
- **Onboarding de cliente** (novo tenant): JSON em `prisma/seed/clientes/<cliente>.json` (organização, municípios/órgãos, usuários iniciais, tipologias/documentos extras) + `npm run onboard -- <cliente> [--demo] [--atualizar] [--redefinir-senhas]` (idempotente; catálogo-base em `prisma/seed/catalogo.ts`; senhas temporárias impressas uma vez, ou `ONBOARD_SENHA`). Demo de Riachão: `npm run onboard -- riachao-das-neves --demo && npm run seed:riachao-demo` (admin.rdn@, tecnico.rdn@, gestor.rdn@, fiscal.rdn@licenciagov.demo). Railway: `scripts/predeploy.sh` (`SEED_ONBOARDING`, `SEED_RIACHAO_DEMO`, `SEED_DEMO`, `RESET_DB` – ver `deploy/railway.md`).
- Dev: `npm run dev`. Vários servidores no mesmo checkout: `NEXT_DIST_DIR=.next-x npx next dev -p 3005`.
- Checagens: `npm run typecheck`, `npm run lint`, `npm test` (vitest, `tests/unit`), `npm run test:e2e` (Playwright, `tests/e2e`).
- Chromium para PDF: `CHROMIUM_PATH` (no container de dev: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`).

## Convenções obrigatórias
- **Escopo multi-município**: toda query de negócio usa `whereMunicipio(u)` / `whereProcessoEscopo(u)` de `lib/rbac.ts`; acesso por URL a registro fora do escopo → `forbidden()`/403 (use `podeVerMunicipio`). Nunca confiar no front.
- **Isolamento por organização (tenant)**: usuário interno pertence a uma organização (`usuario.organizacao_id`; requerente = NULL, global). A sessão (`carregarUsuario` → `lib/sessao.ts`) traz `organizacao_id` e `municipios_org`; papéis de organização (ADMIN, TEC_CONSORCIO, SEMA_INEMA) enxergam só os municípios da SUA organização – `escopoMunicipios()` sempre devolve lista explícita e `whereMunicipio()` nunca é `{}`. Configuração (tipos de ato, tipologias, prazos, checklists, modelos) filtra com `whereOrganizacao(u)`; técnicos com `whereTecnicosEscopo(u)`; pessoas/RTs com `wherePessoaEscopo`/`whereResponsavelEscopo` (`lib/cadastros/escopo.ts`); admin com `lib/admin/escopo.ts` (`organizacaoDoAdmin`, `whereUsuariosAdmin`, `whereMunicipiosAdmin`). Nunca usar `prisma.organizacao.findFirst()` para "a organização": use a do usuário/município. Exportação (`lib/export/exportar.ts` `filtroTabela`) só leva linhas da organização; tabela nova precisa de regra lá. Motor de alertas aceita `{ organizacao_id }`. Testes: `tests/unit/rbac.test.ts`, `orgao.test.ts`, e2e `t12-isolamento`.
- **Permissões**: `can(usuario, acao, recurso, municipioId?)` (`lib/rbac.ts`). SEMA_INEMA é somente leitura: esconder botões de ação (`isSomenteLeitura`).
- **Auditoria**: toda escrita chama `auditar({usuario_id, acao, entidade, entidade_id, antes, depois}, tx?)` (`lib/audit.ts`).
- **Sessão**: páginas usam `exigirUsuario({interno:true})`; Server Actions/rotas usam `getUsuario()` e checam permissão de novo.
- **Órgão ativo**: no login o órgão pode ser escolhido na hora (validado por `podeAcessarOrgao(u, id)`) ou depois (único permitido → automático; vários → `/trocar-orgao`, que lista só os permitidos) – papéis municipais só nos seus municípios; ADMIN/TEC_CONSORCIO/SEMA_INEMA nos municípios da sua organização; REQUERENTE em qualquer um. Cookie `lg_orgao`; `getOrgaoAtivo()` (`lib/auth.ts`); troca em `/trocar-orgao`. É **contexto** (cabeçalho, filtro padrão via `filtroMunicipioPadrao()`, município padrão do requerimento), não fronteira de permissão – o escopo continua em `whereMunicipio()`/`can()`.
- **Build sem banco**: a imagem Docker é construída sem banco – toda página que consulta o banco é dinâmica (`export const dynamic = "force-dynamic"` ou uso de cookies/searchParams). Verifique com `DATABASE_URL="postgresql://x:x@127.0.0.1:1/nada" NEXT_DIST_DIR=.next-nodb npx next build`.
- **Balcão** (`/processos/novo`): servidor protocola em nome do requerente reusando o wizard compartilhado `components/processo/wizard-requerimento.tsx` (`modo: "requerente" | "balcao"`) e os mesmos serviços (`salvarRascunho` com `requerente_id`/`rt_id`, anexos, `transicionar("protocolar")`). Regra `podeProtocolarNoBalcao(u, municipioId)` (`lib/rbac.ts`: ADMIN, TEC_CONSORCIO, TEC_MUNICIPAL, GESTOR_MUNICIPAL; nunca FISCAL/SEMA/REQUERENTE) checada em cada serviço; tramitação registra "Protocolado no balcão por {nome}".
- **API** `/api/v1/*`: handlers envolvidos em `rota()` de `lib/http.ts`; erros `{code,message,details}`; paginação `?page=&size=` via `paginacao()`; validação com zod.
- **Numeração**: `lib/numeracao.ts` (dentro de `prisma.$transaction`).
- **Prazos**: `lib/prazos.ts` (`calcularPrazo`, `etapaAnalise`, `saldoDias`) e `lib/dias.ts` (`semaforo`).
- **Documentos oficiais**: sempre via `emitirDocumento()` / `cancelarDocumento()` de `lib/documentos` (PDF + QR + código verificador + sha256). Documento emitido é imutável.
- **PDF**: `htmlParaPdf()` + `esc()` de `lib/pdf.ts`. Imagens (brasão, logo da organização) sempre embutidas como data URI via `lib/imagem.ts` (`lerImagem`/`imagemDataUri`; lê de `public/`). Logo horizontal da organização (`organizacao.logo_url`, `logoProprio()`) no cabeçalho dos PDFs/relatórios e no portal do órgão; brasão nos lugares pequenos. **Arquivos**: `lib/storage.ts` (`validarUpload`, `salvarArquivo`, sha256 de `lib/crypto.ts`).
- **Dados pessoais**: CPF/CNPJ, e-mail e telefone de PF cifrados (`cifrar/decifrar`), busca por `hashBusca`; portal público usa `mascararCpfCnpj` e `abreviarNome`.
- **UI**: componentes em `components/ui.tsx` (Card, CabecalhoPagina, Badge, BadgeStatus, PontoSemaforo, Aviso, Campo, Paginacao); classes utilitárias `btn-primario`, `btn-secundario`, `btn-perigo`, `card`, `input`, `label`, `tabela`. Mapa: `components/mapa` (`<Mapa />`, só cliente). Menu interno: `components/nav-interno.tsx`.
- Textos em português; datas `dd/mm/aaaa` e moeda `R$` via `lib/format.ts`. Responsivo a partir de 320 px, labels em todos os campos.
- **Monitoramento por satélite** (`docs/monitoramento.md`): alertas DETER/PRODES do INPE em `alerta_desmatamento`, cruzados com CAR (SICAR) e licenças locais – `lib/monitoramento/*`, fila `monitoramento-sync` (06:30) ou `npm run monitoramento:sync [-- SIGLA]` (com `NODE_USE_ENV_PROXY=1` no container). Só municípios com código IBGE real; a demo usa alertas fictícios (`prisma/seed/monitoramento-demo.ts`). Sugestão de situação nunca é aplicada automaticamente.
- Tabelas `tramitacao` e `log_auditoria` são imutáveis (trigger no banco).
- **Demandas urbanas** (APC poda/corte, ASE som em evento, ACS carro de som): regras puras em `lib/demandas/catalogo.ts` (campos do serviço, condicionantes-padrão, `erroDecisaoDemanda`, validade); catálogo em `prisma/seed/catalogo.ts` (onboarding/`seed:base` acrescentam itens faltantes em orgs existentes). Fluxo simplificado: `exige_parecer=false` → técnico do município decide (`decisao_tecnico` em `ContextoAcao`), distribuição automática no protocolo, prazo = `prazo_analise_dias` do ato. Campos específicos ficam em texto estruturado em `processo.descricao_atividade` (`serializarDadosDemanda`/`lerDadosDemanda` – sem coluna JSON). Telas: `/servicos` (portal), `/demandas` (fila + ficha com vistoria). Modelos PDF `templates/autorizacao-poda.ts`/`autorizacao-som.ts` (`chaveModeloEspecifico`). Demo opcional: `npm run seed:demandas-demo` (`SEED_DEMANDAS_DEMO`), fora das contagens dos E2E.
- **Agente de denúncias** (`docs/agente-denuncias.md`): canais em `lib/canais/` (normalizam para `InboundEvent`), orquestração em `lib/agente/` (máquina de estados em código; IA OpenRouter opcional – sem `OPENROUTER_API_KEY` vira questionário determinístico). Denúncias do canal só via `criarDenunciaCanal()`; mudança de situação da denúncia notifica o cidadão (`notificarStatusDenuncia`). Tabela nova → regra em `filtroTabela()` da exportação. Testes/homolog: `CANAIS_ENVIO_SIMULADO=true`.
- **Cobrança de taxas** (`docs/cobranca.md`): Pix/boleto via Asaas na conta do próprio município (`ConfigCobranca`, chave cifrada, nunca devolvida), `TabelaTaxa` (tipo de ato × fase × porte × potencial; a linha mais específica vence), `Cobranca` por processo/fase (UNICA/ANALISE no protocolo, VISTORIA, EMISSAO após deferimento). Tudo via `lib/cobranca` (`gerarCobranca`, `baixaManual`, `isentar`, `processarWebhookAsaas`, `exigirPagamento`); gate em `lib/processo/transicionar.ts` quando `exige_pagamento`. Webhook `/api/v1/webhooks/asaas/[token]` sempre 200. Sem config ativa = fluxo inalterado (E2E não ativa cobrança; demo opcional `npm run seed:cobranca-demo`, RDN/AUM). `PAGAMENTOS_SIMULADO=true` não chama o Asaas. Datas só-dia (vencimento): `fmtDataCivil`.
- **Assinatura digital** (`docs/assinatura-digital.md`): `emitirDocumento()` assina o PDF (PAdES, `lib/assinatura`) com o certificado A1 aplicável (e-CPF do servidor → e-CNPJ do município → e-CNPJ da organização); sem certificado = assinatura eletrônica avançada (Lei 14.063/2020). sha256 sempre do PDF assinado. `.pfx`/senha cifrados, nunca logados nem exportados. Demo: `npm run seed:certificado-demo` (certificado de TESTE, sem valor legal).
- **GED – Gestão de Documentos** (`docs/ged-design.md` é a fonte da verdade do módulo): módulo habilitado por cliente (`organizacao.modulos` inclui `GED`), UI em `app/(ged)/ged/*`, API em `/api/v1/ged/*`, regras em `lib/ged/*`. Papéis próprios (`GedMembro`/`GedPapel`) – nunca em `Papel`/`UsuarioPapel`. **Isolamento entre clientes é o requisito nº 1**: toda tabela `Ged*` tem `organizacao_id` (NOT NULL, primeiro campo dos índices) e toda consulta passa por `gedDb(organizacao_id)` (`lib/ged/db.ts`, único módulo de GED que importa `lib/db`; proibido `$queryRaw/$executeRaw` fora de `lib/ged/busca.ts`); triggers do banco (`ged_mesmo_tenant`) rejeitam referência a linha de outra organização; arquivos em `ged/{organizacao_id}/…` só por rota autenticada (nunca URL pública); registro de outro cliente → 404. Tabela `Ged*` nova precisa de regra em `filtroTabela()` e descrição em `DESCRICAO_TABELA` (teste `ged-schema` falha sem elas). `ged_tramite`, `ged_comentario`, versões seladas e assinaturas registradas são imutáveis (trigger). Anonimização: modelo pronto (sensibilidade, `contem_dados_pessoais`, `anonimizacao_status`, derivado ligado ao original); o motor é futuro – portal público só expõe o derivado (`whereExposicaoPublica`). **OCR** (`docs/ged.md` §13): PDF digitalizado → nova versão `origem=OCR` via `ocrmypdf` (`lib/ged/ocr/*`, fila `ged-ocr`, cota `GedConfig.ocr_cota_paginas_mes`, `ocr_status` por versão); OCR nunca cancela assinatura aberta nem roda em versão selada/assinada; worker dedicado `JOBS_FILAS=ged-ocr`. Sem cobrança no módulo. Jobs em `jobs/ged-*.ts` (registro em `jobs/ged.ts`). Demo fictícia: `npm run seed:ged-demo` (`SEED_GED_DEMO`). Nome exibido ao cliente: "Gestão de Documentos". **Protocolo** (`docs/ged.md` §14; livro de entrada/saída/interno + portal do cidadão): `lib/ged/protocolo/*`, tabelas `GedProtocolo*` (registro **imutável** por trigger, andamento só-INSERT, dados pessoais do interessado cifrados + `hashBusca`), numeração `PROT-ENT|SAI|INT-ano-000123` por cliente/livro, comprovante PDF (PAdES do órgão se houver certificado) em `GedDocumento` origem `COMPROVANTE`; portal público `/protocolo/{slug}` (`organizacao.slug_publico`, **desligado por padrão**, ligado em `/ged/admin/configuracoes`), consulta só com número + código, verificação `/verificar/protocolo/{código}`; rotas públicas resolvem o cliente por `resolverSlugPortal` (só ids) e o resto via `gedDb`; anti-abuso em `limites.ts`; slug inexistente/portal desligado = 404.
- Nunca commitar segredos; `.env*` é ignorado (exceto `.env.example`).
